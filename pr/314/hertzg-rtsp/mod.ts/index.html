An RTSP connection over any { readable, writable } byte pair. Terminology follows RFC 7826 (RTSP 2.0); the message syntax is the same for RTSP/1.0, which is what cameras speak, so the version is just a field.

TCP octets
   |
streams/decode    TransformStream<Uint8Array, RtspMessage | InterleavedBinaryData>
   |
client read loop
   |-- RtspResponse           -> resolves request() by CSeq
   |-- RtspRequest            -> onRequest handler, answer written back
   '-- InterleavedBinaryData  -> channel(channelId), or dropped and counted

The client carries messages and $ blocks, nothing more. It keeps no RTSP session state, does not parse the Transport header or SDP, and does not authenticate. It does not open the socket either: the caller passes the two sides of a connection it already has. Any pair with getReader() and getWriter() will do (OctetSource and OctetSink), so the web streams of this runtime and what Duplex.toWeb(socket) returns both go in as they are.

A request names its method and its Request-URI. The rest may be left out: the version is RTSP/1.0 unless the request or the client's rtspVersion option says otherwise, and there are no header fields besides CSeq and no message body.

The headers of a message are [name, value] pairs, one per header line, in the order of the lines and with each name as written. What the caller passes goes out in that order and that spelling, and what a camera sends comes back the same way. new Headers(response.headers) looks a name up whatever its case.

Every layer is its own entry point: encoding/interleaved, encoding/message, protocol/request, protocol/response, protocol/message, streams/decode, streams/encode and client.

Examples

Send a request and read its response

import { assertEquals } from "@std/assert";
import { createClient } from "@hertzg/rtsp";

const toServer = new TransformStream<Uint8Array, Uint8Array>();
const toClient = new TransformStream<Uint8Array, Uint8Array>();
const client = createClient({
  readable: toClient.readable,
  writable: toServer.writable,
});

const response = client.request({ method: "OPTIONS", requestUri: "*" });

const { value: sent } = await toServer.readable.getReader().read();
assertEquals(
  new TextDecoder().decode(sent),
  "OPTIONS * RTSP/1.0\r\nCSeq: 1\r\n\r\n",
);

await toClient.writable.getWriter().write(
  new TextEncoder().encode("RTSP/1.0 200 OK\r\nCSeq: 1\r\n\r\n"),
);
assertEquals((await response).statusCode, 200);

await client.close();

Describe a camera stream over a TCP socket

import { connect } from "node:net";
import { Duplex } from "node:stream";
import { createClient } from "@hertzg/rtsp";

const socket = connect({ host: "192.0.2.10", port: 554 });
const client = createClient(Duplex.toWeb(socket));

const response = await client.request({
  method: "DESCRIBE",
  requestUri: "rtsp://192.0.2.10/stream1",
  headers: [["Accept", "application/sdp"]],
});
const sdp = new TextDecoder().decode(response.messageBody);

await client.close();

Client = { request: (request: ClientRequest) => Promise<RtspResponse>; channel: (channelId: number) => ReadableWritablePair<Uint8Array, Uint8Array>; droppedBlocks: ReadonlyMap<number, number>; close: () => Promise<void>; }

An RTSP client, made by createClient.

  • channel: (channelId: number) => ReadableWritablePair<Uint8Array, Uint8Array>

    Claims a Channel ID (0 to 255) and returns its two sides.

  • close: () => Promise<void>

    Ends the connection: closes the writable side once everything written has gone out, cancels the readable side, rejects the requests still waiting and closes the readable side of every claimed channel.

  • droppedBlocks: ReadonlyMap<number, number>

    How many $ blocks were dropped, by Channel ID, because nobody had claimed that Channel ID when they arrived. A live view: it changes as blocks are dropped.

  • request: (request: ClientRequest) => Promise<RtspResponse>

    Sends a request and resolves with its final response.

OctetReader = { read(): Promise<

| { done: true; value?: unknown; }
>; cancel(reason?: unknown): Promise<void>; }

The reader of an OctetSource: what the client calls to take the octets the server sends. A ReadableStreamDefaultReader<Uint8Array> is one.

  • cancel(reason?: unknown): Promise<void>

    Tells the connection that nothing more will be read.

  • read(): Promise<
    { done: false; value: Uint8Array; }
    | { done: true; value?: unknown; }
    >

    Resolves with the next chunk, or with done: true when the server has ended the connection. Rejects when the connection failed. Whatever value comes with done: true is not looked at.

T
OctetWriter = { write(chunk: Uint8Array): Promise<void>; close(): Promise<void>; abort(reason?: unknown): Promise<void>; }

The writer of an OctetSink: what the client calls to send octets to the server. A WritableStreamDefaultWriter<Uint8Array> is one.

  • abort(reason?: unknown): Promise<void>

    Ends the writable side at once, dropping what has not gone out.

  • close(): Promise<void>

    Ends the writable side once everything written has gone out.

  • write(chunk: Uint8Array): Promise<void>

    Sends one chunk. The client waits for it to resolve before it writes the next one, and takes a rejection as the failure of the connection.
